- (decision) PRD topic is Tenant Onboarding / Tenant Provisioning for Flexi, focused on automating and standardizing new tenant workspace creation.
- (decision) Direct users are internal Operations, Customer Success, and System Admin users; customer self-service signup is out of scope for this phase.
- (decision) Stakes calibration: UI is an internal tool, but backend provisioning is product-critical and security-critical due to schema isolation and failure recovery risk.
- (decision) Desired product flow: internal form collects tenant identity, subdomain, plan, and first-admin email; validates uniqueness; starts background provisioning; shows step progress; returns setup link or sends setup email on success.
- (decision) Source inputs for this PRD are the schema-per-tenant implementation guide, architecture spine, tenant onboarding SPEC and failure modes, plus schema-per-tenant research artifacts.
- (event) Discovery source extraction completed for Flexi tenant onboarding SPEC, failure modes, schema-per-tenant implementation guide, architecture spine, and current provisioning landscape.
- (decision) Working mode selected: Fast path; draft PRD will use assumption tags for inferred gaps and iterate after review.
- (decision) Form factor is web Super Admin Dashboard plus backend/API provisioning workflow; no mobile or desktop-specific surface in this phase.
- (decision) Phase 1 plan handling: plan is stored and displayed as metadata only; entitlement and feature-flag enforcement is deferred to a later phase.
- (decision) Phase 1 failed provisioning controls are view-only in UI: show FAILED state, failed step, and basic error log; no Retry or Cleanup UI actions.
- (decision) Setup delivery: show the one-time setup link directly in the Super Admin UI for Ops copy as the primary path; automated email is a backup path.
- (decision) Provisioning SLA: target successful provisioning under 1 minute; worker remains async, and attempts exceeding 1 minute should timeout/fail rather than leave the UI spinning indefinitely.
- (event) Retried PRD drafting with neutral internal provisioning-control-plane wording after user reported prior prompt wording triggered policy.
- (event) Initial Fast path PRD draft created with neutral internal provisioning-control-plane language.
- (decision) Bootstrap seed objects before activation: First Admin pending_setup record, default RBAC roles Admin/Manager/Member with permission matrices, workspace system settings, and core lookup data.
- (decision) Email delivery failure is warning-only across all plans; UI shows Email Delivery Failed (Copy Link Manually) and provisioning remains successful if setup link is available in UI.
- (decision) Setup link tokens expire after 24 hours if no existing policy applies; Ops may regenerate setup links from the Super Admin dashboard.
- (decision) API routes use /api/v1/super-admin/tenants for create/list, /api/v1/super-admin/tenants/:id/status for progress polling, and /api/v1/super-admin/tenants/:id/setup-link for setup-link regeneration with standard success/data/error/meta envelope.
- (decision) Ops escalation destination is #ops-escalation-flexi plus runbook URL https://wiki.internal.flexi/runbooks/tenant-provisioning-failure.
- (decision) Migration replay should be revisited for PostgreSQL template schema cloning if p95 provisioning latency exceeds 30 seconds or schema migration files exceed 50, preserving buffer before the 1-minute hard SLA.
- (decision) MVP onboarding history filters are status, subdomain/keyword search matching tenant name or slug, and created_at date range; actor filtering is deferred, actor display remains in table.
- (change) PRD updated with closed open questions: bootstrap seed objects, 24h setup link, warning-only email failure, v1 API routes/envelope, Slack/runbook escalation, MVP history filters, and migration replay revisit threshold.
- (decision) Bootstrap RBAC matrix finalized: Admin full user/role, workspace, business-object, audit access; Manager directory/settings read-only, business CRUD soft-delete, no audit; Member directory read-only, own-record business CRUD, no settings or audit.
- (decision) Setup Link regeneration uses system.tenants.onboard for MVP; a narrower credential-support permission is deferred until distinct support roles exist.
- (decision) Production default seed objects finalized: Draft to In Review to Active to Archived workflow, General/Operations/Administrative categories, and WELCOME_SETUP_INVITE/PASSWORD_RESET_REQUEST/WORKSPACE_LIMIT_WARNING notification templates.
