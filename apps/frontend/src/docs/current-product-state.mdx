# Trạng thái sản phẩm hiện tại

> Đây là điểm bắt đầu để kiểm tra trạng thái sản phẩm hiện tại. Xác nhận thay
> đổi cụ thể bằng mã nguồn và test liên quan.

## Cách đọc bộ tài liệu

1. Đọc trang này để biết phạm vi đang chạy, phạm vi còn trống và các giới hạn
   quan trọng.
2. Xem **UI**, **Shell** và **Pages** để kiểm tra giao diện cô lập.
3. Đối chiếu hành vi nghiệp vụ/API với mã nguồn và test cùng tên trước khi vận
   hành hoặc lập kế hoạch.

## Những route giao diện thật

- `/login` và `/admin/login`: đăng nhập tenant/system.
- `/tenants`: danh sách tenant có phân trang và bộ lọc.
- `/tenants/onboard`: tạo yêu cầu onboarding dành cho system user có quyền.
- Các route module còn lại, gồm `/dynamic-tables`, hiện là trang placeholder;
  điều này không phủ nhận API Dynamic Tables đã có ở backend.

## Quy ước Storybook

Storybook là môi trường kiểm tra giao diện độc lập, không phải môi trường tích
hợp. `MockAuthProvider` và các hàm dữ liệu được truyền vào story là mock có
chủ đích để thể hiện các trạng thái UI như loading, lỗi, phân quyền và dữ liệu
rỗng. Chúng không phải bằng chứng API backend đã hoặc chưa chạy.

Để xác nhận một thay đổi UI, xem story gần component trước. Để xác nhận hành
vi nghiệp vụ/API, xem code backend và test cùng tên.
