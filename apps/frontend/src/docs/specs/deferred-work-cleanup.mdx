# Deferred Work Cleanup Batch

## Intent

**Problem:** `deferred-work.md` had accumulated four small, independent, zero-blast-radius items: a `TenantContext` export-name collision between an injectable class and a param decorator, a Vite `envDir` misconfiguration causing the frontend to silently ignore the documented root `.env`, a missing root `.editorconfig`, and a whitespace-only Tenant ID bypassing the `required` field on the login form.

**Approach:** Fix all four directly: rename the param decorator to `TenantIdHeader` (and its one call site plus two stale doc comments), add `envDir: '../../'` to `vite.config.ts`, add a root `.editorconfig` (with a `[*.py]` 4-space override for the BMad scripts), and add trim/required validation on `LoginPage.tsx`'s Tenant ID field wired through the `Input` component's field-level `error` prop.

## Suggested Review Order

**TenantContext naming collision**

- Entry point: decorator renamed to disambiguate from the unrelated `TenancyClsStore`-backed injectable of the same old name.
  [`tenant-context.decorator.ts:13`](../../apps/backend/src/common/tenant-context.decorator.ts#L13)

- Call site updated to the new decorator name.
  [`auth.controller.ts:39`](../../apps/backend/src/modules/auth/auth.controller.ts#L39)

**Tenant ID whitespace validation**

- Trim-and-reject guard runs before submit, short-circuiting on whitespace-only input.
  [`LoginPage.tsx:37`](../../apps/frontend/src/pages/LoginPage.tsx#L37)

- Field-level error wired through `Input`'s existing `error` prop (aria-invalid/aria-describedby) instead of the generic form banner.
  [`LoginPage.tsx:88`](../../apps/frontend/src/pages/LoginPage.tsx#L88)

**Vite env directory fix**

- `envDir` now points Vite at the repo-root `.env` as the README already documents.
  [`vite.config.ts:8`](../../apps/frontend/vite.config.ts#L8)
