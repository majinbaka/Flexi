## Intent

**Historical problem (resolved):** `apps/frontend` had no auth of any kind — every route was public, and there was no way to obtain/use the JWTs the backend auth API issued.

**Historical approach (implemented):** A Tenant User login page, an `AuthContext` holding an in-memory access token + current user, a localStorage refresh token with silent refresh on boot, an API client that attaches `Authorization` and auto-refreshes once on 401, and a `ProtectedRoute` gating the existing `Layout`. System Admin login was intentionally left to the follow-on Admin Login record, which is now implemented.

## Boundaries & Constraints

**Always:**

- Access token: React state only (`AuthContext`), never persisted, lost on reload. Refresh token: one `localStorage` key; on boot, if present, silently `POST /auth/refresh` before rendering protected routes (block on loading), clearing it on failure.
- Backend envelope: success `{success:true,data:T,error:null}`, failure `{success:false,data:null,error:{code,message}}`. API client unwraps `data`, surfaces `error.code`/`.message`.
- `/login` always sends `x-tenant-id` from a required "Tenant ID" field; `POST {email,password}` to `POST /auth/login`.
- `ProtectedRoute` wraps `<Layout>` in `router.tsx`; no valid access token (none in memory, refresh failed/absent) → redirect `/login`.
- 401 on any call except `/auth/login`/`/auth/refresh` → refresh once, retry; failure → clear state, redirect `/login`. Concurrent 401s share one in-flight refresh (no duplicate rotations).
- Logout: `POST /auth/logout` with current refresh token, then clear all client state + redirect `/login` regardless of outcome.
- New UI text via i18n (`auth` namespace). Styling: inline style objects, matching existing pages.

**Ask First:** None.

**Historical boundary:** Admin Login, reset password, registration, Profile, cookie/session auth and frontend per-route RBAC were out of scope for this change. Admin Login was later implemented; reset password, registration, Profile and frontend per-route RBAC remain incomplete.

## I/O & Edge-Case Matrix

| Scenario                       | Input / State                  | Expected Output               | Error Handling                                   |
| ------------------------------ | ------------------------------ | ----------------------------- | ------------------------------------------------ |
| Login success                  | Valid email/password/tenant id | Tokens stored, redirect `/`   | N/A                                              |
| Invalid credentials            | Wrong password                 | Stay on page                  | Show `error.message` (401 `INVALID_CREDENTIALS`) |
| Boot with stored refresh token | No in-memory access token      | Silent refresh before content | Failure clears storage, renders `/login`         |
| Access token expires           | Authenticated call → 401       | Refresh once, retry           | Refresh failure → logout + `/login`              |
| Logout                         | Click Logout                   | Revoke + clear state          | Redirect `/login` regardless                     |

**Acceptance Criteria:**

- Given no stored refresh token, when visiting a protected route, then redirected to `/login`.
- Given valid credentials + tenant id, when submitting `/login`, then lands on `/` with name + Logout visible in the sidebar.
- Given a stored refresh token from a prior session, when the app boots, then protected routes load without re-entering credentials.
- Given an expired access token, when an authenticated call is made, then it transparently refreshes and completes, or redirects to `/login`.
- Given Logout is clicked, when the request settles, then client state is cleared and the user is on `/login`.
