## Intent

**Problem:** The scaffold's root `pnpm lint` script (`pnpm -r --if-present run lint`) is a silent no-op — no ESLint/Prettier config exists anywhere in the repo — and there is no CI workflow, so code-quality regressions can land silently as more modules and contributors join.

**Approach:** Add a single root ESLint 9 flat config (typescript-eslint + React Hooks/Refresh rules for the frontend) plus a root Prettier config, wire real `lint`/`format`/`format:check`/`test` scripts into the workspace, and add a GitHub Actions `ci.yml` that runs install → build (with an explicit Prisma generate step) → lint → format:check → test on every pull request to `main`.

## Boundaries & Constraints

**Always:**
- One root `eslint.config.js` (ESLint 9 flat config) covering `apps/backend` (Node/CJS), `apps/frontend` (browser/ESM/React), `packages/shared-types` (dual CJS+ESM lib) via targeted `files`/`ignores` blocks — not per-package configs.
- Baseline: `eslint:recommended` + `typescript-eslint` recommended; `eslint-config-prettier` last in the config array so Prettier stays the single formatting source of truth.
- Frontend block additionally uses `eslint-plugin-react-hooks` + `eslint-plugin-react-refresh` (standard Vite React setup).
- Root `.prettierrc.json` + `.prettierignore` (ignore `dist`, `build`, `node_modules`, `pnpm-lock.yaml`).
- New ESLint/Prettier devDependencies declared once, in root `package.json` only (single shared config, no per-package duplication).
- Root `package.json` scripts: `lint` rewritten to invoke ESLint directly (replacing the no-op `-r --if-present` pattern), plus new `format` (`prettier --write`), `format:check` (`prettier --check`), and `test` (`pnpm -r --if-present run test`, so backend's existing Jest suite runs and frontend/shared-types no-op since they define no `test` script).
- New `.github/workflows/ci.yml`: trigger `pull_request` → `main`; steps: checkout, `pnpm/action-setup` pinned to `10.18.0`, `actions/setup-node` (Node 20, pnpm cache), `pnpm install --frozen-lockfile`, `pnpm --filter @flexi/backend prisma:generate` (with a dummy `DATABASE_URL` supplied via workflow `env`, since Prisma `generate` only reads the schema, not a live DB), `pnpm build`, `pnpm lint`, `pnpm format:check`, `pnpm test`.
- Run `eslint --fix` / `prettier --write` (and hand-fix anything left) across existing scaffold source so `pnpm lint` and `pnpm format:check` both exit 0 by the end of this change.

**Ask First:** If a new lint rule surfaces what looks like an actual behavioral bug in existing scaffold code (not just a style/unused-var nit), halt and ask before changing runtime behavior to satisfy the rule.

**Never:**
- Do not reorder or modify the root `build` script's dependency chain (`shared-types` → `backend` → `frontend`); Prisma generate stays a CI-only explicit step, not folded into `pnpm build`.
- Do not add a new test framework (e.g. vitest) for frontend/shared-types — only wire the pass-through `test` script; adding real tests there is separate deferred work.
- Do not configure GitHub branch-protection rules or require the CI check in repo settings — outside version-controlled scope.

## Spec Change Log

## Design Notes

- Single root flat config, not per-package: one shared rule baseline across three packages; per-package configs would be a decision with no payoff at this repo's size — revisit if/when a package (e.g. `shared-types`' public API) needs stricter rules.
- `prisma generate` is an explicit CI step, not folded into `pnpm build`, to avoid touching the existing build script contract; local devs already run it manually per README.
- `eslint-config-prettier` goes last in the flat config array so ESLint only flags logic/correctness issues, never formatting.

## Verification

**Commands:**
- `pnpm install` -- expected: installs new devDependencies cleanly
- `pnpm lint` -- expected: exit 0, no errors
- `pnpm format:check` -- expected: exit 0
- `pnpm build` -- expected: unchanged success (`shared-types` → `backend` → `frontend`)
- `pnpm test` -- expected: exit 0 (backend Jest suite runs; frontend/shared-types no-op via `--if-present`)

**Manual checks (if no CLI):**
- Open `.github/workflows/ci.yml` and confirm the YAML is well-formed and steps are in the intended order (actual GitHub Actions execution can only be verified after pushing/opening a PR).
