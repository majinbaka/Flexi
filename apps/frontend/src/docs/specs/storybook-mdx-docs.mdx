## Intent

**Problem:** `apps/frontend` has no isolated component workshop or a ready-to-run way to view component documentation outside the running app.

**Approach:** Add Storybook to `apps/frontend` using its official Vite+React framework with MDX docs support and add first-example stories for the existing `Layout`/`Sidebar` components. Viewing is via the Storybook dev server — no separate MDX viewer tool is needed.

## Boundaries & Constraints

**Always:** Storybook config lives under `apps/frontend/.storybook`; add it via the official `storybook init` CLI (or hand-authored equivalent) using the `@storybook/react-vite` framework so it reuses the existing Vite 5/React 18 toolchain — no second bundler. Expose it via a `storybook` script in `apps/frontend/package.json` (mirroring `dev`/`build`/`preview`), runnable as `pnpm --filter @flexi/frontend storybook`. New `.mdx`/`.stories.tsx` files must pass existing `pnpm lint` and `pnpm format:check` unmodified (Prettier handles `.mdx` natively; no eslint config changes needed since `apps/frontend/**/*.{ts,tsx}` already covers stories files). Reuse `apps/frontend/src/styles/tokens.css` and the existing i18n setup in Storybook previews.

**Ask First:** If the CLI-resolved Storybook version conflicts with Vite 5.4/React 18.3 and requires a downgrade of either.

**Never:** Do not touch `apps/backend` or `packages/shared-types`. Do not restyle `Layout.tsx`/`Sidebar.tsx` beyond what a story needs. Do not add visual-regression/test-runner addons or a CI job for Storybook — out of scope.

</frozen-after-approval>

## Design Notes

Use the official `storybook init` (or `storybook@latest`) CLI to resolve a mutually-compatible version set for Storybook + `@storybook/react-vite` + docs addon, rather than hand-picking versions in this spec — registry state changes faster than the spec's shelf life. Latest stable at investigation time was Storybook 10.5.8, compatible with Vite 5 and React 18.
