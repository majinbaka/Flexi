## Intent

**Problem:** The Tenants page (`TenantsPage.tsx`) is a Story 1.1 shell with hardcoded empty rows and no backend list endpoint — Ops cannot yet find tenants or see onboarding history from the Super Admin dashboard.

**Approach:** Add a paginated, filterable `GET /api/v1/super-admin/tenants` endpoint joining each tenant with its latest onboarding attempt (status + actor name), and wire `TenantsPage` to fetch, filter, and render it with skeleton loading and empty states.

## Boundaries & Constraints

**Always:**

- Route stays gated behind `JwtAuthGuard` + `PermissionsGuard` + `@RequirePermissions(SYSTEM_TENANTS_ONBOARD_PERMISSION)` — same permission as every sibling endpoint in this controller. `Onboard New Tenant` action in the UI stays gated by the same permission via existing `canOnboardTenants`.
- Response uses the standard envelope (`{ success, data, error, meta }`) via the existing global `ResponseInterceptor`.
- List rows show: tenant name, slug, lifecycle status, plan, created date, latest attempt status, actor name.
- Plan and actor name are read from the tenant's linked `TenantOnboardingAttempt.safePayload.plan` / `.actorIdentity.name`, not stored redundantly on `Tenant`.
- Filters (status, keyword/subdomain matching name or slug, `createdAt` range) are query params combined with AND logic; all optional.
- Actor filtering is explicitly out of scope — actor name is display-only.
- Pagination uses `page`/`pageSize` query params (default `page=1`, `pageSize=20`, max `pageSize=100`, min `1` for both — non-positive or non-integer values are rejected, not clamped); response `meta` includes `total` and `page`/`pageSize` echoed back. UI renders page navigation (prev/next, or page N of M) using `total`/`page`/`pageSize` — no page beyond 1 is otherwise reachable.
- `createdFrom`/`createdTo` must parse as valid dates (`new Date(value)` not `Invalid Date`); an unparseable value is rejected the same as an inverted range.
- Loading state renders skeleton rows sized like the real table (same column count/widths); empty state (`No tenants yet.`) and no-match-state (filtered, zero results) are visually distinct and both come from the same `Table` empty slot, driven by which case is active.
- `Onboard New Tenant` remains the page's primary action, not a sidebar item (already true — do not regress).

**Ask First:**

- If joining attempts requires a schema/index change beyond reading existing `Tenant.onboardingAttemptId` and `TenantOnboardingAttempt` fields, halt and confirm before migrating.

**Never:**

- Do not build attempt detail/timeline, success handoff, failure escalation, or audit drawer views — those are Stories 3.2–3.5.
- Do not add a status-badge design-system component beyond reusing existing `Badge` tones for this story; a dedicated `status-badge` mapping is future epic-3 work, not required here unless trivial.
- Do not add actor-based filtering.
- Do not introduce React Query/SWR or a table library — extend the existing `apiGet`/`Table` primitives.

## Spec Change Log

- **Iteration 1** (review loopback, intent_gap + bad_spec): Blind-hunter review found `GET /v1/super-admin/tenants` as originally specced ("no extra permission beyond authentication") lets any authenticated user — including `ActorType.TENANT` users of any tenant — list every tenant in the system, a cross-tenant data leak; the frozen Intent was wrong, not just the code. Human resolved: gate the route behind `@RequirePermissions(SYSTEM_TENANTS_ONBOARD_PERMISSION)`, matching every sibling endpoint in this controller. Also amended (bad_spec, all three reviewers independently found variants): (1) reject non-positive/non-integer `page`/`pageSize` instead of leaving them unvalidated below the upper clamp; (2) reject unparseable `createdFrom`/`createdTo` date strings instead of silently no-op'ing the range check; (3) require UI page-navigation controls since `total`/`page`/`pageSize` were being returned but never rendered, capping the list at 20 reachable rows. KEEP: the latest-attempt-via-direct-FK join design (no max-by-createdAt subquery), the single shared `where` clause reused by `findMany`+`count`, the safe-placeholder handling for tenants with no onboarding attempt, and the loading/empty/no-match state design in `TenantsPage.tsx` all worked well in the reverted implementation and should be re-derived as-is.
- **Iteration 2** (patch, applied directly, no loopback): Re-review after iteration 1's fixes confirmed the permission gate, page/pageSize validation, date-format validation, keyword escaping, and pagination UI all now work correctly. Two trivial patches applied without re-derivation: (1) a date-only `createdTo` (e.g. `"2026-12-31"`) parsed to midnight UTC, silently excluding the entire day the caller meant to include — `parseFilterDate` now pushes a date-only `createdTo` to `23:59:59.999` of that day so the range reads as inclusive; a `createdTo` that already carries a time component is used as-is. (2) Removed dead conditional `DEFAULT_PAGE_SIZE > 5 ? 5 : DEFAULT_PAGE_SIZE` in `TenantsPage.tsx` (always evaluated to `5` since `DEFAULT_PAGE_SIZE` is `20`) in favor of a plain `skeletonRowCount={5}`.

## Design Notes

Latest-attempt join: since `Tenant.onboardingAttemptId` is a direct FK to exactly one `TenantOnboardingAttempt`, "latest attempt" per tenant is simply that linked attempt — no need for a max-by-createdAt subquery. Use a single Prisma `findMany` with `include: { onboardingAttempt: true }` plus `skip`/`take` for pagination, and a parallel `count()` for `meta.total`, both under the same filter `where` clause built once and reused.

Keyword filter matches tenant `name` OR `slug` via case-insensitive `contains` (Prisma `mode: 'insensitive'`). Escape `%`, `_`, and `\` in the raw keyword before passing to Prisma (e.g. prefix each with `\`) so user input can't act as a SQL `LIKE` wildcard.

Reject non-positive or non-integer `page`/`pageSize` with `VALIDATION_ERROR` (do not clamp the lower bound — only the upper `pageSize` bound clamps). Reject unparseable `createdFrom`/`createdTo` the same way as an inverted range, using `Number.isNaN(new Date(value).getTime())`.
