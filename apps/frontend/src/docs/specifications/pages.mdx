# Pages

## Trạng thái specification gate

Các yêu cầu trong trang này đã được stakeholder xác nhận cho phần mở rộng sau
MVP hiện tại. Chúng là contract cần triển khai, chưa phải hành vi của production
code. Endpoint, DTO, persistence, asset storage, renderer, permission và UI
tương ứng phải được xây dựng và kiểm thử trước khi quảng bá module là khả dụng.

**Gate requirement đã đạt.** Page-builder schema, route ownership,
draft/publish/versioning, component allowlist và permission đã có quyết định.
Cột Prisma `Page.definition` chỉ là nơi chứa JSON hiện tại, không phải contract.
Implementation phải tạo và version hóa một schema contract dùng chung, đồng
thời validate contract ở cả builder và backend.

Ba chi tiết được để cho task implementation lựa chọn mà không thay đổi hành vi
bên ngoài:

- thư viện parser đáp ứng expression contract an toàn;
- schema nằm trong `@flexi/shared-types` hay package page-builder riêng;
- renderer được build cùng SPA hay thành public portal bundle riêng.

## Page-builder schema contract

Definition dùng Flat Node Map `Record<string, PageNode>`. `schemaVersion` mô tả
phiên bản kỹ thuật của JSON contract và độc lập với `revisionNumber`, là số thứ
tự của nội dung đã publish.

```json
{
  "schemaVersion": "1.0.0",
  "rootNodeId": "node_root",
  "state": {
    "selectedRowId": null,
    "filterKeyword": ""
  },
  "nodes": {
    "node_root": {
      "id": "node_root",
      "type": "layout:container",
      "props": { "direction": "vertical", "padding": "md" },
      "children": ["node_heading_1", "node_table_1"]
    },
    "node_heading_1": {
      "id": "node_heading_1",
      "type": "display:heading",
      "props": { "level": 2, "text": "Danh sách khách hàng" },
      "children": []
    },
    "node_table_1": {
      "id": "node_table_1",
      "type": "data:table",
      "props": { "pageSize": 10 },
      "bindings": {
        "dataSource": { "type": "apiResult", "queryKey": "getCustomers" }
      },
      "actions": {
        "onRowSelect": [
          {
            "actionType": "setState",
            "target": "selectedRowId",
            "value": "{{ $event.id }}"
          }
        ]
      },
      "children": []
    }
  }
}
```

Node ID theo dạng `node_[random_hash]` và unique trong một page. Root phải tồn
tại, mọi child ID phải trỏ tới node tồn tại, một node không được tạo cycle và
độ sâu tối đa là 10. Mỗi page có tối đa 500 node và definition JSON tối đa
2 MB.

Layout dùng hệ 12 cột với Flexbox/Grid. Responsive props hỗ trợ `mobile`,
`tablet` và `desktop`. Style chỉ dùng design token và component variant; raw
CSS, raw HTML và inline style tùy ý bị cấm. Text có thể là chuỗi tĩnh hoặc
`{ key, default }` để tham chiếu i18n.

Global Base Allowlist là nguồn sự thật. Tenant plan có thể tắt một component
hoặc nhóm component nhưng không thể đăng ký loại mới trong MVP. `Standard`

nếu được bổ sung sau này, nó là Privileged component và chỉ tải domain nằm

Asset upload dùng presigned URL, giới hạn 5 MB mỗi file, kiểm tra MIME type và
malware trước khi asset được renderer sử dụng. Component không gọi trực tiếp
ra Internet; query và mutation phải qua backend proxy để tái kiểm tra RBAC/ABAC.

Renderer gặp component type/version không nhận diện được phải ghi operational
error và render `UnknownComponentPlaceholder` tại node đó, không làm crash cả
page. Deprecated component tạo warning trong builder; published revision pin
component version và chỉ được migrate bằng quy trình có validation.

## Route ownership

Builder dùng `/admin/pages/:pageId/builder`. Runtime internal dùng
`/:tenantSlug/app/*path`; runtime public dùng `/:tenantSlug/p/*path` hoặc custom
domain. Tenant được resolve từ custom domain/subdomain trước, và authenticated
internal request phải khớp tenant claim trong JWT.

`Page.path` bắt đầu bằng `/`, được lowercase, bỏ trailing slash, khoảng trắng và
chuyển ký tự có dấu thành ASCII slug. Path hỗ trợ dynamic parameter và một
catch-all ở cuối.

Reserved paths gồm `/api/*`, `/login`, `/logout`, `/settings`, `/admin/*`,
`/_health` và `/static/*`. Uniqueness mục tiêu là
`(tenantId, domain, locale, normalizedPath)`, không phải unique constraint hiện
tại. Backend phải phát hiện cả exact collision, ambiguous dynamic pattern và
collision với static system route.

Đổi path của page đã publish có thể tạo `PageRouteRedirect` 301 từ path cũ sang
path mới sau khi kiểm tra redirect loop. Unpublish trả 404. Hard-delete public
route đã từng tồn tại trả 410; archive/soft-delete chưa phải hard-delete.

Preview dùng signed URL ngắn hạn `/api/pages/preview?token=...`, hết hạn sau 12
giờ và có thể chia sẻ nội bộ. Token phải pin tenant, page, draftVersion và quyền
preview; Draft/Preview luôn trả `X-Robots-Tag: noindex, nofollow`.

Published public page hỗ trợ title, description, OG image, canonical URL và cập
nhật sitemap. Locale có thể là prefix `/:locale/path`; locale thiếu nội dung
fallback về `defaultLocale` của tenant.

## Draft, publish và revision

Lifecycle chính thức gồm `DRAFT`, `PUBLISHED`, `UNPUBLISHED`, `ARCHIVED`. Page
mới có mutable `draftDefinition` và bắt đầu ở `DRAFT`.

Save Draft cập nhật mutable draft và tăng `draftVersion`; không tạo revision.
Client bắt buộc gửi `draftVersion` hiện có. Nếu version trong database đã cao
hơn, backend trả `409 STALE_VERSION_CONFLICT`; UI cho phép tải bản mới nhất hoặc
lưu nội dung local thành một page copy. Autosave chạy mỗi 30 giây khi dirty.

Publish strict-validate Draft, tạo immutable `PageRevision` với
`revisionNumber` tăng một và atomically đổi `publishedRevisionId`. Published
revision cũ tiếp tục phục vụ trong lúc Draft được sửa và khi transaction publish
thất bại.

Unpublish xóa published pointer, chuyển sang `UNPUBLISHED` và giữ revision
history. Archive là soft-delete khỏi luồng quản lý thông thường. Rollback copy
snapshot của revision được chọn vào Draft, tăng `draftVersion`, nhưng không đổi
Published revision cho tới lần Publish kế tiếp.

Mỗi page giữ tối đa 50 Published revisions gần nhất. Revision lưu definition
snapshot, metadata, actor, timestamp và change note. Chính sách không được xóa
revision đang published hoặc revision còn được audit/reference; implementation
phải dọn revision vượt retention theo thứ tự cũ nhất sau các ngoại lệ này.

Audit bắt buộc cho `SAVE_DRAFT`, `PUBLISH`, `UNPUBLISH`, `ROLLBACK` và `ARCHIVE`.
Scheduled publication và real-time collaborative editing thuộc v2.

```json
{
  "draftVersion": 14,
  "definition": {
```

Publish response trả page ID, immutable revision ID, revision number và
publication timestamp trong response envelope chung:

```json
{
  "success": true,
  "data": {
    "pageId": "page_123",
    "publishedRevisionId": "rev_99",
    "revisionNumber": 5,
    "publishedAt": "2026-08-26T08:53:59Z"
  }
}
```

## Builder UX và acceptance criteria

Builder hỗ trợ drag-and-drop từ Palette, Tree View, Canvas và Inspector. Undo /
Redo giữ ít nhất 30 thao tác trong phiên, với `Ctrl+Z` và `Ctrl+Y`. Preview có
viewport Desktop 1440 px, Tablet 768 px và Mobile 375 px. Khi `isDirty`, đóng
tab hoặc rời route phải có unsaved-change guard.

### Create và Save Draft

- Given actor có `pages:create`, when tạo “Danh sách đơn hàng” với path
  `/orders`, then Page ở `DRAFT` và builder mở Canvas ban đầu.
- Given actor có `pages:edit`, when thêm Table, binding dữ liệu và Save Draft,
  then backend validate, lưu `draftDefinition`, tăng `draftVersion` và UI xác
  nhận thành công.
- Given client giữ stale `draftVersion`, when Save Draft, then không ghi đè dữ
  liệu mới hơn; API trả 409 và UI cho tải lại hoặc lưu thành bản sao.

### Preview và Publish

- When actor có quyền preview mở Draft hợp lệ, then signed URL pin đúng tenant,
  page và draftVersion, hết hạn sau 12 giờ và render dữ liệu thật hoặc mock đã
  chọn.
- Given actor có `pages:publish`, when nhập change note và Publish một Draft hợp
  lệ, then transaction tạo immutable revision, đổi published pointer và ghi
  audit.
- Given strict validation thất bại, when Publish, then Published revision hiện
  tại không đổi và builder hiển thị lỗi gắn với node/JSON Path.

### Runtime và Rollback

- Given page có Published revision, when authenticated user truy cập
  `/:tenantSlug/app/orders`, then renderer dùng đúng immutable snapshot và mọi
  binding/action được backend tái kiểm tra permission.
- Given page có `isPublic = true`, when anonymous visitor truy cập public route,
  then chỉ dữ liệu được policy cho phép công khai được trả về.
- Given actor chọn revision v1 và Rollback, then v1 được copy vào Draft và
  Canvas cập nhật; Published revision không đổi cho tới lần Publish sau.
- Runtime page mục tiêu hiển thị trong dưới 500 ms; task implementation phải
  định nghĩa phép đo và môi trường benchmark trước khi biến mục tiêu này thành
  release gate tự động.

Trước khi bỏ stub, UI phải có loading, empty, validation error, permission
denied, save conflict, publish failure, unknown component và expired-preview
states. Backend phải có test tenant isolation, RBAC, schema limits, route
collision/precedence, atomic publish, stale update, revision retention, public
access, secret masking và audit.
