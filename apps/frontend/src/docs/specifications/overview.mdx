# Specifications

Các trang này là đặc tả sống được đối chiếu với code hiện tại. Chúng mô tả
hành vi đã có và target contract được gắn nhãn rõ; target/backlog không phải
cam kết rằng tính năng đã hoạt động. API backend hiện có tiền tố `/api` và phản
hồi dùng envelope `{ success, data, error }`; các đề xuất `/api/v1` hoặc Problem
Details vẫn chờ ADR chung, không phải convention đã triển khai.

## Mô hình năng lực hợp nhất

Nhóm **Product Capability Model** là điểm vào cấp nền tảng:

- **Overview** — executive summary, capability matrix, aggregate map,
  cross-module contracts, lifecycle, security và end-to-end acceptance criteria.
- **Roadmap & Backlog** — roadmap Low-code MVP → Production-ready v1 →
  Enterprise v2 theo dependency, cùng Epic → Feature → Story.
- **Decisions, Risks & Specs** — mâu thuẫn, ADR/Decision Log, Risk Register và
  danh mục specification cần viết/cập nhật.

Các trang module bên dưới tiếp tục là nguồn chi tiết và bằng chứng
implementation. Khi có khác biệt, Decision Log phải được chốt trước khi một
module tự chọn contract riêng.

## Phạm vi chưa đặc tả như một chức năng hoàn chỉnh

`workflows`, `pages`, `cron-jobs`, `mail-templates`, `wiki`, `i18n`,
`settings` và `logs` hiện có route nhận diện module nhưng backend trả
`{ status: 'not-implemented' }` và frontend hiển thị `PlaceholderPage`.
Không có flow nghiệp vụ hoàn chỉnh để đặc tả từ code hiện tại.

Riêng `settings`, trang **Core System Configuration** lưu contract mục tiêu và
đối chiếu với phần bootstrap đã có; nó không tuyên bố module đã khả dụng.

## Cách kiểm tra

- Xem story cạnh trang UI để kiểm tra loading, lỗi, empty và permission UI.
- Chạy unit test frontend (Vitest, `*.spec.tsx` cạnh source) cho hành vi
  component/hook; chạy Jest unit/e2e của backend cho hành vi API.
- Đối chiếu endpoint với controller/service được ghi trong mỗi trang.
- Storybook dùng mock có chủ đích; kết quả story không thay thế kiểm thử tích
  hợp với backend/database/queue.
