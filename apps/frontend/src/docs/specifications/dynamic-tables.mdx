# Dynamic Tables API

## Phạm vi hiện có

Backend cung cấp tạo bảng động, sửa field bất đồng bộ, theo dõi DDL job và
CRUD row theo metadata trong schema của tenant. Route frontend
`/dynamic-tables` vẫn là `PlaceholderPage`; chưa có table/field builder UI.

Mọi API thật nằm dưới `/api/tables` và cần JWT tenant-scoped cùng permission
phù hợp. `JwtAuthGuard` lấy schema chỉ từ claim tenant đã verify, còn
`TenantKnexService` schema-qualify mọi query/DDL; System actor không có tenant
context nên không thể dùng API này thành công.

## Bảng và DDL

Create-table yêu cầu `name` và tối thiểu một field. `RELATION` không được tạo
ở request tạo bảng, nhưng được thêm qua field edit cùng `relatedTableId`.
Tên bảng/field được sanitize và không được dùng prefix `_meta_`. DDL không
chạy trong HTTP request: service enqueue BullMQ job; worker tái lập tenant
context, chạy DDL qua Knex, và ghi trạng thái vào `_meta_migrations`.

Một `modify` đổi `dataType` dùng chuỗi expand/backfill/cutover thay vì đổi
type in-place. Đổi sang hoặc rời `RELATION` bằng modify bị từ chối; cần remove
rồi add lại. Worker có guard cho các step có thể replay sau retry.

## Row validation và dữ liệu

Metadata `_meta_tables` và `_meta_fields` quyết định table vật lý và schema
validation. Chỉ field metadata được whitelist trước khi insert/update; vì vậy
payload không thể ghi `id` hay timestamp quản lý hệ thống. Create kiểm tra
field required; PATCH chỉ kiểm tra field có trong payload. Type/check config
gồm min/max length, min/max number và enum của SELECT.

Relation nhận integer ID. Foreign key của Postgres kiểm tra target row; lỗi
FK được đổi thành `400 VALIDATION_ERROR`. Khi đọc list/detail, relation được
resolve thành row liên quan hoặc `null`. Pagination/rate limit cho row list
chưa được xác nhận từ implementation hiện tại.
