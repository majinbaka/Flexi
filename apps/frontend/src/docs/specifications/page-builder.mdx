## 1. Mục tiêu và phạm vi

Flexi Page Builder là engine dựng giao diện kéo-thả theo cơ chế declarative,
tạo các trang web đa thiết bị mà không cho phép thực thi JavaScript tùy ý. Trang
được biên dịch thành Flat Node Map và render tại runtime bằng React Component
Registry đã qua kiểm duyệt.

## 3. Yêu cầu chức năng

### 3.1. Builder Canvas và Core Engine

- **Flat Node Map:** lưu UI tree dưới dạng `Record<NodeId, Node>` để lookup
  node theo ID với độ phức tạp kỳ vọng O(1), thay vì phải duyệt cây sâu.
- **Autosave và conflict:** lưu Local Draft mỗi 10 giây vào LocalStorage/Redis.
  Optimistic locking phát hiện hai người cùng sửa; UI cho phép Fork Draft,
  Overwrite hoặc Discard.
- **Undo/Redo:** Command Pattern lưu tối đa 50 thao tác trong session.
- **Keyboard accessibility:** phím mũi tên điều hướng Node Tree;
  `Ctrl+C/V`, `Delete`, `Ctrl+Z/Y` lần lượt copy/paste, xóa và undo/redo.

### 3.2. State Management và Data Engine

- **Safe Expression Parser:** binding như
  `{'{{ queries.getUser.data.name }}'}` phải chạy qua AST parser an toàn; cấm
  `eval()` và `new Function()`.
- **Query lifecycle:** trigger `On Page Load` hoặc `Manual Action`; hỗ trợ
  debounce, cache TTL và tối đa ba lần auto-retry với exponential backoff.
- **Repeating context:** Container/List lặp danh sách và cấp scope con `item`,
  `index` cho các node bên trong.

### 3.3. Component UI và Form System

- Mỗi field hỗ trợ Required, Min/Max, Regex và validation động dựa trên state.
- Table, List và Cards phải cấu hình được Skeleton Loading, Empty State và
  Query Error Retry.
- Node có thể ẩn/hiện hoặc disabled theo RBAC hay safe expression.
- Cụm node có thể đóng gói thành Section Template; instance có thể
  `Sync all instances` hoặc `Detach instance`.

### 3.4. Layout, SEO và routing

- Breakpoint mục tiêu: Desktop trên 1024 px, Tablet từ 768–1023 px và Mobile
  dưới 767 px; CSS override được lưu riêng theo breakpoint.
- Public Page cấu hình Meta Title, Meta Description, OG Image, robots directive
  và Dynamic OpenGraph bindings.

## 7. Lifecycle và state machine

### 7.1. Page status

```text
[Draft] -- Submit Review --> [In Review] -- Approve --> [Published]
   |                                                    |       |
   +---------------- Direct Publish --------------------+       |
                                                                |
                              Rollback --> Draft mới <-----------+
                                                                |
                              Archive ----------------> [Archived]
```

State machine này cần được chuẩn hóa khi triển khai vì nguồn yêu cầu vừa mô tả
`In Review`, vừa cho phép Direct Publish. Prisma hiện chỉ lưu `status` dạng
string, mặc định `draft`, nên chưa enforce transition nào.

### 7.2. Runtime Engine lifecycle

1. **Init:** tải Page Layout JSON theo URL route.
2. **Theme Hydration:** nạp Design System Tokens vào CSS Variables context.
3. **Store Initialization:** khởi tạo User Context, Route Params và Page State.
4. **Data Query Execution:** chạy query `On Page Load` song song hoặc theo DAG.
5. **AST Evaluation:** bind state vào component props.
6. **Virtual DOM Render:** chuyển Flat Node Map thành React elements.
7. **Action Event Loop:** nhận event, chạy pipeline, cập nhật state, đánh giá lại
   AST và render lại.

## 9. Security và tenant isolation

- Mọi layout query phải scope theo `tenant_id` của request context.
- Dynamic Text/HTML phải sanitize trước khi render; raw HTML không nằm trong
  component allowlist mặc định.
- Mutate Record/Trigger Workflow phải rate-limit theo IP và user ID, dự kiến
  bằng Redis Token Bucket.
- Runtime proxy không tin `tenant_id` hoặc secret do client truyền; tenant đến
  từ JWT/session đã xác thực, secret đến từ server-side `SecretKeyRef`.

## 11. Acceptance criteria

### AC-01 — Autosave conflict

- **Given** Designer A và B cùng mở Draft v1 của `Page_101`.
- **When** A lưu để server tăng lên v2, sau đó B autosave từ v1.
- **Then** API trả `409 Conflict` và không âm thầm ghi đè v2.
- **And** UI cho B tải bản mới, Fork Draft hoặc yêu cầu Overwrite theo quyền.

### AC-02 — Data Query thất bại tại runtime

- **Given** `User_Dashboard` có Table bind với query `getOrders`.
- **When** query trả `500 Internal Server Error`.
- **Then** Table chuyển sang Error Fallback “Không thể tải dữ liệu” với nút
  “Thử lại”; các phần khác của page tiếp tục hoạt động.

### AC-03 — Tenant isolation trong data binding

- **Given** User X thuộc `Tenant_A` truy cập `Public_Report`.
- **When** page kích hoạt query qua backend proxy.
- **Then** proxy lấy tenant từ token/session hợp lệ và gắn tenant context.
- **And** `tenant_id` cố ý truyền từ URL/client bị bỏ qua hoặc từ chối.
