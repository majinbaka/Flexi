# Workflows

## Trạng thái specification gate

Các yêu cầu trong trang này đã được stakeholder xác nhận cho phần mở rộng sau
MVP hiện tại. Chúng là contract cần triển khai, chưa phải hành vi của production
code. Endpoint, DTO, persistence, queue/worker, permission và UI tương ứng phải
được xây dựng và kiểm thử trước khi quảng bá module là khả dụng.

**Gate requirement đã đạt.** Trigger/action model, revision/runtime lifecycle,
retry/idempotency, permission và audit đã có quyết định. Không được suy diễn
schema từ cột Prisma `definition`; implementation phải tạo contract được
version hóa theo đặc tả dưới đây.

### Trigger context và recursive execution

Dynamic Table context bắt buộc có `tenant_id`, `table_id`, `record_id`,
`actor_id`, `timestamp`, `event_type` và `snapshot`. Event payload đồng thời có
`before`/`after` theo quy tắc ở trên.

Action Dynamic Table được phép kích hoạt workflow khác. Tự kích hoạt chỉ được
phép khi workflow bật `allow_recursive`. Mọi trigger chain mang
`execution_depth`; depth tối đa là 5. Loop detector chặn khi cùng
`workflow_id` thay đổi cùng `record_id` quá ba lần trong 10 giây.

### Webhook security và availability

- Secret chỉ hiển thị một lần khi tạo. Rotate chấp nhận secret cũ và mới trong
  grace period 24 giờ; revoke có hiệu lực ngay.
- Inactive workflow trả `422 WORKFLOW_INACTIVE`; Archived workflow không để lộ
  endpoint và trả `404`.
- Ưu tiên idempotency identity từ `Idempotency-Key`, sau đó `X-Request-ID`.
  Khi thiếu cả hai, fallback là SHA-256 của raw request body.
- Dedupe identity được scope bằng hash của
  `tenant_id + workflow_id + dedupe_key`, nên cùng payload tới hai workflow
  không xung đột.
- External caller được định danh là `SYSTEM_WEBHOOK_CALLER`, kèm origin IP và
  kết quả xác thực HMAC trong audit; không persist secret/signature raw.

### Scheduled ownership và overlap

Publish/Activate đăng ký lịch với Cron Jobs; Deactivate/Archive hủy đăng ký để
ngăn trigger mới. Overlap policy gồm `SKIP` mặc định, `QUEUE` tối đa năm runs,
và `CANCEL_PREVIOUS`. Cron Jobs chỉ làm đồng hồ thực thi; người dùng không cần
quản lý cùng một lịch ở hai module.

## Action model và flow control

Workflow là DAG chạy tuần tự và hỗ trợ node If/Else với tối đa hai nhánh
True/False. Không cho cycle; validate khi Save Draft và Publish. Một workflow có
tối đa 100 steps và If/Else lồng tối đa năm cấp.

Kết quả từng bước được đưa vào context chung theo
`steps.<stepId>.output`; trạng thái chuẩn nằm ở `steps.<stepId>.status`. Input
của bước sau có thể là giá trị cố định hoặc tham chiếu context.

### Validation và failure behavior

Condition hỗ trợ `String`, `Number`, `Boolean`, `Array`, `Null` cùng các
operator `EQUALS`, `NOT_EQUALS`, `GREATER_THAN`, `LESS_THAN`, `CONTAINS`,
`STARTS_WITH`, `IS_EMPTY`, `IN`. Biến thiếu hoặc `null` được đánh giá là
`null`; `IS_EMPTY` trả true. So sánh sai kiểu trả false và không throw runtime
exception.

Dynamic Table action dùng transaction độc lập ở cấp action. Update/Delete không
tìm thấy record mặc định làm step failed; `ignore_missing` đổi kết quả thành
success với `affected_rows: 0`. Không mở transaction xuyên qua HTTP hoặc
notification step.

Run mặc định dừng ở `failed` khi một step thất bại sau khi hết retry. Step có
`continue_on_error: true` cho phép luồng tiếp tục và Condition phía sau kiểm tra
`steps.<stepId>.status == "FAILED"`.

### HTTP security

HTTP timeout mặc định 30 giây, cấu hình tối đa 120 giây; response body tối đa
5 MB và theo tối đa ba redirects. Runtime chặn private/link-local/loopback
targets, gồm RFC 1918, RFC 4193, `127.0.0.1` và `169.254.169.254`, kể cả sau
DNS resolution/redirect. Tenant có thể cấu hình domain allowlist.

Secret chỉ được tham chiếu bằng `{{secrets.SECRET_KEY}}`; runtime resolve khi
thực thi và mask khỏi log/output/audit.

### Context persistence

Step output được giữ 30 ngày, tối đa 2 MB mỗi step. Trước khi persist hoặc hiển
thị, hệ thống redact các field nhạy cảm như `password`, `token`,
`authorization`, `secret`, `credit_card` thành `***REDACTED***`. Giới hạn và
redaction được áp dụng cả với response ngoài và Test Run live.

Workflow mới bắt đầu ở runtime `Inactive` cùng một Draft revision. Publish là
Save & Activate. Quy trình publish tăng revision, đăng ký đầy đủ Cron/webhook/
event listener mới, rồi mới atomically chuyển revision cũ sang Superseded. Nếu
registration lỗi, revision Published cũ và listeners cũ tiếp tục hoạt động;
Draft không trở thành runtime contract.

Edit Active/Inactive workflow không sửa Published revision và không đổi runtime
state. Mọi run pin `revision_id` cùng immutable snapshot lúc bắt đầu. Publish
revision mới không thay đổi run đang thực thi.

Deactivate giữ Published revision để Activate lại mà không cần Publish. Run Now
từ list/record chỉ dùng Published revision gần nhất, kể cả workflow đang
Inactive. Test Run trong designer dùng Draft và mock input. Rollback nhân bản
Superseded revision thành Draft mới rồi Publish; publish rollback tự Activate.

Archive ngăn trigger mới nhưng cho run hiện tại graceful drain. Tenant Admin có
thể restore; workflow trở lại Inactive với Draft để review trước lần Publish kế
tiếp. Concurrent Draft edit dùng optimistic locking theo `updated_at`/
`revision_version` và trả `409` khi lost-update conflict.

### Test Run sandbox

Dynamic Table write trong Test Run dùng mock schema hoặc transaction không
commit. HTTP và Notification có toggle Mock/Live. Chỉ Developer hoặc Tenant
Admin được xem Test Run output; mọi Live Execution vẫn chịu permission,
redaction, timeout và audit như run thường.

## Retry, idempotency và concurrency

retryable có một lần đầu và tối đa ba retries, với backoff 2s, 4s, 8s cùng
jitter ±500ms.

## Audit và retention

Audit bắt buộc cho `create`, `edit`, `publish`, `activate`, `deactivate`,
`archive`, `trigger_accepted`, `trigger_rejected`, `retry_step`,
`mark_success`, `secret_rotation`, `secret_revocation` và
`permission_denied`.

Mỗi record có `id`, `tenant_id`, actor `id/type/ip`, `workflow_id`,
`revision_id`, `run_id`, `action`, `outcome`, `diff_summary` và `timestamp`.
Audit là append-only, tenant-isolated và giữ một năm. Operational run log cùng
persisted step context giữ 30 ngày. Archive không xóa lịch sử hoặc audit.

Không bao giờ persist plaintext Authorization header, webhook secret, API
token, password hoặc raw email content nhạy cảm. Payload/output còn lại phải qua
redaction trước khi lưu hoặc render. Chỉ Tenant Admin được export audit dưới
dạng CSV hoặc JSON Lines.

## Acceptance criteria trước khi thay stub

- Save Draft và Publish reject schema sai, cycle, quá 100 steps hoặc If/Else
  sâu quá năm cấp; concurrent edit trả `409` mà không mất thay đổi.
- Publish chỉ swap revision/listeners khi mọi registration thành công; lỗi giữ
  nguyên Published runtime cũ. Run luôn dùng revision snapshot đã pin.
- Mỗi trigger type tạo đúng context và dedupe identity; duplicate trong 72 giờ
  trả original run ID và không tạo run/side effect mới.
- Retry chỉ replay action lỗi, không replay step đã success. HTTP result không
  xác định pause run và chỉ tiếp tục sau manual resolution được audit.
- Tenant isolation và RBAC được kiểm thử cho definition, sensitive payload,
  lifecycle, execution, manual resolution và audit export.
- Webhook HMAC, rotation/revoke, payload limit, inactive/archive response, SSRF,
  secret masking, output size và retention đều có test.
- UI phải có loading/empty/error/conflict, Draft/Published/runtime states, retry
  progress, paused resolution và permission-denied behavior trước khi bỏ
  PlaceholderPage.
