# Specs & Architecture

This section is the preserved design and decision history for Flexi. It
contains implementation specifications, architecture decisions, story
breakdowns, failure-mode analysis and review records originally produced in
the planning/build process. It is useful for answering **why** and **what was
intended**, but it is not the source of truth for current release status.

Start with [Current Product State](/docs/current-product-state--docs) for a
code-based summary and the audit report. Non-spec product, UX, research and
process documentation remains in the top-level
[`docs/`](../../../../docs) folder; `docs/README.md` is its index.

## Reading order

| Need                               | Read first            | Then use                                              |
| ---------------------------------- | --------------------- | ----------------------------------------------------- |
| Verify what is currently available | Current Product State | The audit report and implementation code it links     |
| Understand a current feature       | Its SPEC              | Its numbered build stories and tests                  |
| Understand a technical choice      | Architecture Spine    | Architecture diagrams and review records              |
| Plan unfinished work               | Current Product State | `docs/process/deferred-work.md` and the relevant SPEC |

## Status convention

The pages below retain historical statements such as “deferred”, “done” or
“stub” in their original context. Treat them as dated design records. The
audit identifies where implementation has since changed, for example Dynamic
Tables and Tenant Onboarding now have substantive backend behavior despite
older scaffold language.

## Architecture and review history

- Architecture Spine -- the platform's lean spine of invariants (design
  paradigm, stack, AD-\* architecture decisions).
- Review - Adversarial / Rubric / Web Verify -- the review passes the
  spine went through before being adopted.

## Tenant Onboarding

Epic 1 (intake), Epic 2 (provisioning), and Epic 3 (tenants list) specs
for the super-admin tenant-onboarding flow, each epic's context summary,
the standalone Super Admin Tenant Onboarding SPEC + failure modes, and the
3-tier RBAC brainstorm that seeded it.

## Dynamic Table Builder

The SPEC, architecture diagrams, and the four build stories (tenant-schema
metadata, table/field CRUD via the async DDL queue, row read/write API,
many-to-one linked records) for the dynamic table builder module.

## Auth & Tenancy Core

Core authentication (backend + frontend), admin login, auth rate limiting,
refresh-token reuse detection, and the schema-per-tenant-core pivot spec.

## Platform & Tooling

Scaffold, lint/CI tooling, editorconfig drift check, the Figma design sync
and Storybook MDX docs specs (the specs that built this doc-viewing setup
itself), and the deferred-work/fixes-batch cleanup specs.
